WHEETTLE TICKETING SYSTEM - TEN-DAY DEVELOPMENT WORK PLAN
Day 0 through Day 9 | Draft allocation prepared 15 September 2026

This is a proposed sequence from initial planning through live deployment. Each day groups related technical work and its expected output. Effort depends on requirements, defects, feedback and environment readiness; the wording does not certify long hours or completed overtime. Record actual dates, work periods and results. Local implementation already exists; deployment/live acceptance remain pending.

DAY 0 - REQUIREMENTS AND FUNCTIONALITY DOCUMENTATION
Reason: To consolidate the system requirements, define project scope and user roles, map ticket-handling and employee-reference workflows, specify file-attachment and reporting requirements, document access rules and validation criteria, identify open questions, and prepare and review the functionality document and progress guide as the basis for development.
Tasks:
- Define intended users, ticket ownership, statuses, priorities and closure rules.
- List employee-reference data, history, departments and account requirements.
- Specify attachment formats, size/count limits and download access.
- Map screens, reports, export fields, acceptance checks and exclusions.
- Format the DOCX, review consistency and establish the progress guide.
Output: Functionality DOCX, requirements checklist and initial progress guide.

DAY 1 - DETAILED DATABASE SCHEMA DESIGN AND CREATION
Reason: To design and create the database schema by defining tables, columns, data types, required and optional values, primary and foreign keys, unique constraints, indexes and relationships for users, permissions, employee references, departments, tickets, assignments, comments, activity history and file attachments; prepare migration scripts and fictional seed records, then validate referential integrity and database connectivity.
Tasks:
- Map relationships and determine which records own or reference each item.
- Define identifiers, timestamps, statuses, text lengths and edit-version fields.
- Design attachment metadata and private binary storage linked to tickets.
- Add constraints and indexes for filtering, history and ticket lookups.
- Prepare fresh-install and additive migration scripts; review data preservation.
- Check table creation, foreign keys, sample inserts and query connectivity.
Output: Versioned schema/migrations, relationship notes and fictional fixtures.

DAY 2 - SHARED BACKEND, AUTHENTICATION AND ACCOUNT FUNCTIONS
Reason: To develop the shared application functions for configuration, database access, session handling, sign-in and sign-out, password changes, role permissions, account creation and activation, input validation, request protection and error handling, and connect these functions into a consistent application foundation before building individual business workflows.
Tasks:
- Implement database helpers and application initialization.
- Build authentication, password hashing and mandatory first-password change.
- Implement account creation, activation/deactivation and session revocation.
- Add role checks, CSRF protection and common validation/error handling.
- Check restricted actions and prepare reusable helpers for feature modules.
Output: Shared backend and working account-access functions.

DAY 3 - TICKET, EMPLOYEE-REFERENCE AND HISTORY FUNCTIONS
Reason: To develop business functions for ticket creation, employee linking, assignment, priority and status updates, comments, resolution, closure and reopening, together with employee-reference maintenance and manually recorded changes; implement validation, transactional saves, activity records and conflicting-edit protection so related information remains consistent through each workflow.
Tasks:
- Implement ticket creation and reference generation.
- Add ownership, status, priority, comment and resolution operations.
- Implement employee fields, assignments, employment dates and history notes.
- Record before/after changes with actor and effective/recorded dates.
- Add transaction rollback and stale-save handling for concurrent edits.
Output: Core ticket, employee-reference and history functions.

DAY 4 - FILE ATTACHMENTS, SEARCH AND REPORTING FUNCTIONS
Reason: To implement ticket file uploads, filename/content validation, count and size limits, private storage and authenticated downloads; develop ticket and staff filtering, pagination, dashboard aggregates, date-based reports and CSV exports, and connect these functions to the core records while checking permission boundaries and report definitions.
Tasks:
- Accept supported files during ticket creation and save them transactionally.
- Reject unsupported, malformed, oversized and excessive uploads.
- List attachments on ticket details and enforce ticket access on downloads.
- Build search/filter queries, pagination and dashboard summary queries.
- Implement report metrics and CSV generation with consistent date semantics.
Output: Attachment, search, reporting and export functions.

Tasks:
- Build shared page layouts, navigation, forms and data tables.
- Add attachment selection, limits guidance and download links.
- Connect actions to backend functions and display validation feedback.
- Apply role-aware controls and consistent labels/status indicators.
- Check mobile tables, form spacing, error states and workflow links.
